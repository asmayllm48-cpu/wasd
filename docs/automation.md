# الأتمتة المتقدمة — اكتشاف الألوان والمفاتيح المتقدمة والمنطق الشرطي

> طبقة مستقلة أُضيفت إلى المشروع الحالي. لم يتغير محرك العرض أو الاتصال أو جودة الفيديو أو طريقة عمل المفاتيح القديمة.
> هذا الملف = دليل الاستخدام + التوثيق الهندسي + التقرير النهائي.

الملفات:

| الملف | الوصف |
|---|---|
| `src/core/automation.{h,cpp}` | المنطق النقي: الألوان والمناطق والمراقبات ومحرك تنفيذ السيناريو والتخزين بصيغة JSON |
| `src/app/automation_runtime.cpp` | وصلة المحرك بالجلسة الحية: قراءة منطقة من الإطار، وإرسال اللمس، وضغطات المفاتيح |
| `src/app/automation_ui.cpp` | واجهة المحرر: الالتقاط، الدوائر على صورة اللعبة، المراقبات، وخطوات السيناريو |
| `src/core/profile.{cpp,h}` | حفظ القسم الجديد داخل ملف اللعبة ومنع تعارض المفاتيح |
| `tests/test_automation.cpp` | 11 اختباراً جديداً ضمن محصلة 56 اختباراً ناجحاً |

## 1. اكتشاف الألوان

طريقة المقارنة: نحوّل كل بكسل ولون الهدف إلى فضاء CIELAB ونقيس المسافة Delta E 76.
ولكل لون قيمة تسامح منفصلة (المنزلق 0–60، الافتراضي 12). هذه الطريقة تتحمل
اختلاف الإضاءة وضغط الفيديو أفضل من تطابق RGB الحرفي.

المنطقة الدائرية (Zone):

- تُخزَّن الهندسة كنِسَب لكل إطار الهاتف: المركز من 0 إلى 1، ونصف القطر نسبة من ارتفاع الإطار.
- لذلك تبقى صحيحة عند تغيير حجم النافذة أو دقة الهاتف أو الاتجاه.
- العَدّ يقتصر على البكسلات داخل الدائرة نفسها؛ وإن كانت قراءة الـ Renderer مربعًا محيطًا بها فلا يدخل الخارج منه في الحساب.
- شرط الوجود: عدد البكسلات المطابقة لا يقل عن «Min pixels»، وإن فُعِّلت النسبة فيجب تجاوزها أيضًا.
- نمط «Any» يكفيه أي لون من القائمة، ونمط «All» يطلّب ظهور كل الألوان معًا.
- الحدود: 16 لونًا لكل منطقة، و16 منطقة كحد أقصى.

Color Picker:

1. انقر «+ Add color (pick from the game)» ثم انقر على النقطة الملونة داخل صورة اللعبة (Esc يلغي).
2. يُقرأ اللون من إطار الفيديو الحي (قراءة 2×2 عبر خانات الـ Renderer نفسها — بلا مسار فيديو ثانٍ).
3. يظهر اللون بصيغة #RRGGBB مع معاينة مربعة، وعدد البكسلات المطابقة لحظيًا، وزر Re-pick لإعادة الالتقاط، وزر حذف.

## 2. محرك المراقبة (Monitors)

إعدادات كل مُراقب: المنطقة، فترة الفحص (10–5000 مللي ثانية)، عدّاد التأكيد
Confirm (Debounce)، فترة التهدئة Cooldown، الانتظار Delay بعد الاكتشاف،
نمط التكرار، ثم الإجراء (تشغيل Macro أو ضغط مفتاح).

قاعدتان مهمتان:

- المُراقب الجديد معطَّل حتى تحدد إجراءه بنفسك؛ لا يوجد إجراء افتراضي.
- فحص الشاشة منفصل عن تكرار التنفيذ: فحص كل 20 مللي ثانية لا يعني تنفيذ الأمر كل 20 مللي ثانية.

أنماط التكرار:

| النمط | السلوك |
|---|---|
| Once | مرة واحدة عند أول ظهور ثم توقف نهائي |
| Repeat while visible | تنفيذ متكرر طول بقاء الشرط مع احترام Cooldown |
| Again after it disappears | ينفّذ عند الظهور، ولا ينفّذ جديدًا حتى يختفي ويظهر مجددًا |
| Limited count | عدد محدد من المرات ثم توقف |

ضد التكرار الخاطئ: تأكيد الاكتشاف بفحوصات متتالية، فترة Cooldown،
عدم تشغيل إجراء ثانٍ والإجراء السابق ما زال مشغولًا، وإسقاط الفحوصات المتأخرة
(الفحص الذي لم يصل خلال 250 مللي ثانية يُرمى ولا يُنفَّذ لاحقًا).

## 3. الحالة والإحصاءات

مؤشر الحالة في لوح الأتمتة:

- أخضر: المراقبة تعمل.
- أحمر: المراقبة متوقفة.
- برتقالي: وضع الاختبار Live test.
- رمادي: لا يوجد فيديو (الميزة غير جاهزة).

تحت المؤشر: سبب آخر توقف، ثم إحصاءات حية — معدل الفحص في الثانية،
زمن الفحص p50، وعدد عمليات الاكتشاف. وعند فقدان الفيديو أو فصل الهاتف
تتوقف المراقبة تلقائيًا مع عرض السبب.

## 4. المفتاح المتقدم (Advanced Macro)

نوع جديد من المفاتيح، مستقل عن المفاتيح الموجودة: له اسم، ومفتاح
إطلاق يُسجَّل بالنقر على الزر ثم ضغط المفتاح، وحد أقصى للزمن.

شكل المحرر:

- لكل خطوة صف مستقل فيه: مربع تفعيل، وقائمة تغيير النوع، وأزرار نسخ وحذف، وأزرار تحريك لأعلى/أسفل.
- كل نوع له لون مميز: الانتظار رمادي، الشرط بنفسجي، الحلقة برتقالية، الأنواع الإيقافية حمراء، والبقية سماوية.
- الصف الجاري تنفّذه الآن يُظلَّل بالأخضر.
- إحداثيات الخطوات تُدخل رقميًا أو بالالتقاط: زر Pick ثم النقر على المكان داخل صورة اللعبة.

محرك التنفيذ:

- بلا انتظار حاجب: كل انتظار مؤقت يُستأنف في حلقة التحديث الرئيسية، فالواجهة لا تتجمد أبدًا.
- حالات التنفيذ: Idle / Running / Waiting / Completed / Cancelled / Failed.
- عند الإلغاء أو الفشل أو تجاوز الزمن: تحرير كل الأصابع المضغوطة وكل المفاتيح المعلّقة بأمان، ثم عرض سبب التوقف.
- حدود صلبة: 500 خطوة في القائمة، عمق تداخل 8، و10,000 تكرار للحلقة، وزمن أقصى للسيناريو.
- زر STOP (emergency) ظاهر دائمًا خلال التنفيذ، ومفتاح F8 يوقف كل شيء فورًا.

أنواع الخطوات المنفذة فعليًا (لا شيء إلا المختبر):

| النوع | الوسائط |
|---|---|
| Wait | مدة بالميلي ثانية |
| Tap / Press down / Release | نقطة + رقم الإصبع (0–4) |
| Long press | نقطة + مدة + إصبع |
| Swipe / Drag | نقطة بداية + نقطة نهاية + مدة + إصبع |
| Key | مفتاح مسجَّل + وضع Press/Hold/Release |
| Run macro | Macro آخر من القائمة |
| IF / ELSE | منطقة لونية أو صورة مرجعية + عكس الشرط NOT + مساران مستقلان |
| Loop | عدد مرات أو While/Until على لون أو على صورة + حد أقصى + توقف بين الدورات |
| Break / Stop | إنهاء الحلقة أو السيناريو كله |
| Comment | ملاحظة غير منفذة |
| Image recognition | صورة مرجعية + إعدادات بحث (عتبة، منطقة، مهلة، إعادة محاولة، بحث مستمر) + إجراء عند العثور (نقر داخل إطار التطابق، نقرة/مطولة/مزدوجة، تسلسل خطوات، ماكرو، قفز لخطوة، إيقاف) + إجراء عند عدم العثور (متابعة، إعادة، تسلسل بديل، قفز، إيقاف، فشل) |

مثال تسلسل (المفتاح F):

1. انتظر 200 مللي ثانية ← Tap A ← انتظر 300.
2. Press down B ← Swipe من B إلى C خلال 250 ← Release.
3. انتظر 150 ← مفتاح R.
4. النقاط A وB وC تُلتقط من صورة اللعبة أو تُدخل رقميًا بدقة ثلاث خانات.
5. جرّب بـ Test run وشاهد الخطوة الجارية تتقدم.

## 5. IF / ELSE / LOOP داخل السيناريو

- الشرط IF يُبنى من قائمة الخطوات: اختر المنطقة المفحوصة (بنفس الألوان والتسامح المعرفة لديها) وخيار عكس الشرط NOT.
- يُنفَّذ مسار واحد فقط: مسار THEN عندما يتحقق الشرط، أو مسار ELSE عندما لا يتحقق. المساران قائمتان مستقلتان بنفس أدوات التحرير.
- الحلقة Loop بثلاثة أنماط: Repeat N times لتكرار محدد، وWhile color present للتكرار طالما اللون موجود، وUntil color present للتكرار حتى يظهر اللون. حد Max times هو حد الأمان للتكرار، وPause ms انتظار بين كل دورة.
- Break ينهي دورة الحلقة فقط، وStop يوقف السيناريو كله.
- التداخل مسموح حتى عمق 8، وRun macro يستدعي Macro آخر بنفس الحدود.
- الفحص داخل الشرط يعتمد آخر عملية قراءة مخزنة للمنطقة (حتى 500 مللي ثانية)؛ وإن انقطع فيديو الهاتف تمامًا يفشل السيناريو بأمان برسالة واضحة ولا يختار مسارًا خطأً.

## 6. الأداء

- الفحص يقرأ مربع الدائرة المحيط فقط، لا الإطار كاملاً.
- لكل منطقة خانة قراءة خاصة من خانات الـ Renderer، وتحدد أقصر فترة مراقبة على تلك المنطقة إيقاع طلبها.
- عند وجود فحص معلَّق لم يكتمل، يُتجاهل الطلب الجديد بدل تراكم الفحوصات.
- استهلاك الفحص متناسب مع بكسلات الدوائر وفترة الفحص، لا مع دقة الإطار كاملة.
- إحصاءات حية ظاهرة دائمًا (معدل/ثانية، زمن p50، عدد الاكتشافات) لقياس الأثر على جهازك.
- الحالة المستقلة عن FPS: بدون تعديل على دقة العرض أو جودة الترميز أو الحساسية أو سلوك التحكم القديم.
- عند فقدان الفيديو: إلغاء فوري للسيناريو النشط وإيقاف للمراقبة مع عرض السبب.

## 7. الأمان والاستقرار

- البيانات تُتحقَّق عند التحميل ومع كل تعديل (`validateAutomation`)، وتُعرض الأخطاء كنص صريح.
- لا تنفيذ نصوص أو أوامر نظام من ملفات الإعدادات؛ المحرك ينفذ أنواع الخطوات المحددة فقط.
- إحداثيات وأزمنة وقيم خارج الحدود تُرفض، وإذا فشل أمر أثناء التنفيذ يتوقف السيناريو وفق سياسة آمنة مع تحرير كل الضغطات.
- إيقاف طارئ فوري دائم (الزر ومفتاح F8).
- إيقاف نهائي عند فصل الهاتف، بلا أي إعادة تشغيل تلقائي.
- الأحصاءات ظاهرة لكل مراقب: عدد مرات التنفيذ (runs) ووقت آخر اكتشاف.
- أداة أتمتة محلية لأوامر التحكم المذكورة؛ لا آليات لتجاوز الحماية أو إخفاء الأتمتة.

## 8. الحفظ

الكل يُحفظ داخل ملف اللعبة الحالي (نفس آلية التخطيطات): مفتاح الطوارئ، المناطق وألوانها وتسامحها، الإجراءات والخطوات، شروط IF/ELSE وأوضاع LOOP وإعدادات المراقبة. ملف قديم بلا قسم أتمتة يعمل كما هو، والبيانات التالفة تُرفض بتحقق صريح.

## 9. الاختبارات

11 اختبارًا ضمن محصلة 64 (511 تأكيدًا) كلها ناجحة:

1. مطابقة اللون: تسامح، Min pixels، أنماط Any/All.
2. العد داخل الدائرة فقط.
3. مراقب Rearm: تنفيذ لكل ظهور مع Debounce.
4. مراقب Continuous/Limited مع Cooldown ومنع تنفيذ مزدوج والإجراء مشغول.
5. ترتيب الخطوات مع انتظار غير حاجب.
6. مسار IF/ELSE واحد فقط، وتكرار LOOP بالعدد، وBreak.
7. تحرير الضغطات عند الإلغاء، وإيقاف الحلقة اللامحدودة بحد الزمن.
8. فشل آمن برسالة عند غياب إطار الفحص.
9. دورة حفظ/تحميل داخل Profile مع بقاء الملفات القديمة سليمة.
10. رفض البيانات غير الصالحة.
11. التعرف على الصور (16 اختبارًا): عثور دقيق، رفض نسيج مختلف، احترام منطقة البحث، مقياس ±10%، متانة السطوع، دورة JSON، وخطوة Image recognition الموحدة (نقر بالمنتصف، إزاحة مخصصة، نقرة مزدوجة، تسلسل خطوات، قفز، متابعة/تسلسل بديل/فشل عند عدم العثور، حد المحاولات، إلغاء أثناء البحث، سياسة الأقرب) وترحيل الخطوتين القديمتين Image search/Click image.

## 10. حدود اكتشاف الألوان

- التسامح يقاس بمسافة CIELAB وهو تقريب جيد لكنه ليس مثاليًا لكل الحالات؛ اضبط قيمة كل لون على حدة.
- ضغط الفيديو H.264/H.265 قد يمزج درجات البكسل قليلًا؛ اختر ألوانًا من مناطق ثابتة اللون بعيدًا عن الحواف.
- تعتمد النتيجة على آخر قراءة للمنطقة (أقر من 500 مللي ثانية)؛ وإن كان المحتوى يتغير سرعة كبيرة جدًا فارفع عدد عينات التأكيد أو فترة الفحص.

## 11. أول تشغيل على جهازك

1. وصّل الهاتف وشغّل `build\wasd.exe`.
2. زر `+ Add zone` ثم انقر مكان الدائرة في صورة اللعبة؛ أسحب مركزها أو مقبض نصف القطر على الحافة، أو أدخل الأرقام من المنزلقات في اللوح.
3. زر `+ Add color` ثم انقر على اللون المطلوب داخل الصورة؛ عدّل التسامح إن لزم.
4. فعّل `Live test` وراقب عدد البكسلات المطابقة لحظيًا بجوار كل لون.
5. زر `+ Add monitor` — اختر المنطقة ونمط التكرار ثم حدد الإجراء (Macro أو مفتاح) قبل تفعيله.
6. زر `+ Add macro` — اربط مفتاح الإطلاق ثم ابنِ الخطوات بترتيبها من «+ Add step»، وجرّب `Test run`.
7. كل التعديلات تُحفظ مع ملف اللعبة بنفس زر الحفظ المعتاد.

## 12. حصيلة التسليم

**مكتمل ومنفذ ومختبر:**

- اختيار الألوان من الإطار الحي مع تسامح CIELAB لكل لون.
- مناطق دائرية قابلة للسحب والتحجيم على صورة اللعبة، حسب نسب إطار الهاتف.
- تحقق مراقِبات بأربعة أنماط تكرار مع Debounce وCooldown وتأكيد الاكتشاف.
- محرك Macro غير حاجب بآلة حالات، وبكل أنواع الخطوات ذات الوسائط المذكورة.
- شرط IF/ELSE وحلقات LOOP بأنماطها الثلاثة، مدمجة مع محرر المفاتيح الموجود.
- حفظ واستعادة داخل ملف اللعبة، مع 11 اختبارًا للأتمتة ضمن 56 اختبارًا كليًا ناجحًا.

**لم يُنجَز في هذه الجلسة ويتبقى:**

- قياس أداء «قبل/بعد» مسجلًا بأرقام على جهاز حقيقي (يتطلب جهاز المستخدم).
- الاختبار اليدوي للواجهة: سحب الدائرة والتقاط الألوان وتشغيل سيناريو على لعبة فعلية.
- تجربة المستخدم الكاملة مع ألعاب متعددة على أجهزة مختلفة.

**معيار النجاح:** أن تنشئ منطقة مراقبة دائرية، وتختار الإجراء عند الاكتشاف، وتربط مفتاحًا بسلسلة متقدمة، وتبني شروطًا وحلقات من واجهة مرئية — مع بقاء المحرك الأصلي سريعًا ومستقرًا. جميع هذه النقاط منفذة في الكود ومختبرة بالاختبارات الآلية؛ واختبارها اليدوي على لعبتك هو الخطوة الأخيرة عليك.
